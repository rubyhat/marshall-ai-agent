# Persist and Handoff Reference Findings

Keep chat-first analysis lightweight and durable reference packs canonical.

## Confirm persistence authority

Persist only when the user explicitly asks to add, save, document, refresh, or update the reference, or when project policy provides equivalent exact authority.

An analysis request without that language remains chat-first. Do not create a file merely because the result is substantial.

## Reconcile before creating

Use configured maps to search:

1. the root reference registry;
2. the exact external project pack;
3. the relevant domain map;
4. matching flow, surface, focused, or comparison artifacts.

Apply `skip → link → update → create`. Update an existing canonical artifact when subject and scope match. Create a new artifact only for a distinct durable role.

## Select an artifact

Use project-local templates first. Use bundled fallback templates only when project policy allows and no local template applies:

- `assets/templates/project-map.md`;
- `assets/templates/domain-map.md`;
- `assets/templates/surface-inventory.md`;
- `assets/templates/flow-analysis.md`;
- `assets/templates/surface-analysis.md`;
- `assets/templates/focused-analysis.md`;
- `assets/templates/comparison.md`.

Do not create every map or inventory for a focused request. Create a domain map when the domain has enough artifacts to need navigation. Create a surface inventory only for intentionally broad product mapping.

## Write a durable current-state artifact

- Use the configured language and naming.
- Record access or observation dates and freshness limitations.
- Keep source links and evidence labels near the claims they support.
- Separate observation, documentation, inference, unknowns, and adaptation.
- Link decisive permitted captures; do not embed an unbounded media archive.
- Replace stale current-state wording or preserve dated variants only when history itself is useful.
- Update applicable maps after the artifact is valid.

## Hand off without expanding authority

Report what was created or updated and which findings remain evidence rather than decisions.

- Product decisions require shaping.
- Target interaction behavior requires design.
- Task and specification artifacts require their own authority.
- Content production requires the owning marketing or copy workflow.
- Implementation never follows directly from a reference pack.
